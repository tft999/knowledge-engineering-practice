# CookKG 单页菜单规划器 UI 设计

## 目标

构建桌面优先、兼容平板的中文单页应用。用户输入库存、常备调料、排除项、菜数和补购上限后，页面展示菜单方案、联合补购清单、库存覆盖、可选省略和来源证据；局部知识图谱通过右侧抽屉解释推荐与排除关系。

首版使用明确标识的模拟数据独立完成 UI。FastAPI 完成后只替换 API 实现，不修改页面领域模型。

## 页面结构

- 顶部项目栏显示 CookKG、简短说明、数据状态和“演示数据”标记。
- 主体最大宽度 1440px。1024px 以上采用 360px + 1fr 两栏，左侧条件面板保持粘性；768px 至 1023px 上下排列。
- 条件面板包含已有食材、常备调料、排除项、菜数、最多补购数、载入示例和提交按钮。
- 结果区依次显示候选数、补购数、库存利用数、约束状态和最多五个方案卡。
- 菜谱详情在方案卡内按需展开；局部图谱在右侧抽屉中显示。

## 视觉规范

- 浅灰页面、白色卡片、深灰文字和蓝色主操作。
- 绿色表示库存覆盖，琥珀色表示补购，红色表示排除或错误，紫色表示食材类别。
- 使用系统中文字体，不加载远程字体，不使用渐变、插画或玻璃效果。
- 图谱中菜谱、食材、类别和工具节点使用蓝、绿、紫、灰；必需关系为实线，可选关系为虚线，排除路径为红色。
- 状态必须同时使用文字或符号表达，不能只依赖颜色。

## 交互行为

- 初始表单为空，菜数默认为 2，最多补购默认为 2，返回方案固定为 5。
- “载入演示示例”填入鸡蛋、洋葱、面包片；盐、食用油、黄油、料酒；排除辣椒。
- 标签输入支持 Enter、中英文逗号、去空格、字段内去重和 Backspace 删除。
- 相同文本不能同时出现在可用集合与排除集合中。别名冲突由后端归一化后判断。
- 新提交取消前一个请求并保留表单。无解、字段错误、网络错误和图谱错误分别展示。
- 来源链接在新标签页打开并设置 `noopener noreferrer`。

## 数据边界

页面只依赖 `CookKgApi`：推荐、菜谱详情和单菜局部图谱。模拟和 HTTP 实现遵循同一接口。API 模块校验未知 JSON 并转换为领域对象，组件不直接处理原始响应。

推荐响应使用嵌套菜谱摘要，并包含归一化输入、扩展排除项和最多五条解释。HTTP 200 且方案为空表示业务无解；422 表示输入错误；图谱失败不能清除主结果。

## 图谱抽屉

- 使用 Radix Dialog 实现宽度 `min(640px, 92vw)` 的右侧抽屉。
- 菜单含多道菜时在顶部切换菜谱，每次只请求一道菜、最多 30 个节点。
- React Flow 使用按节点类型分列的确定性布局，支持缩放、拖动、适应视图和节点选择。
- Escape 关闭抽屉，焦点返回触发按钮。

## 验收

- 1440×900 和 768×1024 视口无横向溢出。
- 用户可仅用键盘完成载入示例、提交、展开详情和打开/关闭图谱。
- 模拟模式明确显示，成功、层级排除、无解、服务失败和图谱失败均可复现。
- 组件测试、类型检查、生产构建和 Playwright 核心流程通过。
