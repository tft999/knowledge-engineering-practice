# HowToCook 食材图谱与菜单规划设计

## 目标
课程首轮交付数据与推荐闭环，创新点是多道菜联合补购优化。
支持 1—3 道菜、最多补购种类、已有食材、显式常备调料及排除食材。
不是完整 GraphRAG：网页、嵌入检索和真实模型问答在后续阶段实现。

## 架构
Python 3.13；Pydantic 校验标准数据；NetworkX 有向图；Typer CLI；
Neo4j 官方驱动提供可选持久化；pytest 和 Ruff 验证。
固定 HowToCook 提交 `2b19c9e9ee926fd925a68207a57582a338813f9c`。
原始与生成数据忽略入 Git，来源版本、许可、审核规则及少量测试样例入 Git。

## 数据与审核
菜谱以源文件相对路径标识，食材以标准名称标识；原始用量、证据行号、
来源提交链接均保留。实体为菜谱和食材；使用关系状态为 required/optional/pending。
分类与难度为属性，步骤保留原文。名称字典仅归并确认的同义词。
解析原料、计算、操作章节并交叉检查；模板跳过，缺失或歧义信息报告。
严格推荐仅采用内容哈希匹配的人工审核记录，规则解析成功不等于人工审核。
至少 10 道真实菜谱逐份审核；审核记录可补充原文中遗漏的常备原料、工具和可选分支。
工具保留为元数据，不作为可食用原料。未知工具需求不声明为已满足。

## 推荐
按食材种类判断，无重量库存；常备调料默认为空。
排除必需食材的菜谱，省略被排除的可选食材；仅使用已审核且无 pending 的菜谱。
单菜按缺料数量升序、覆盖已有非调料食材数降序、ID 排序，截取前 60 道。
枚举所选菜数的组合，补购为必需食材并集减已有与常备调料，超过上限则过滤。
按补购少、覆盖多、排序后的菜谱 ID 排序，输出前 5 组及来源。
只承诺候选池内最优；无解说明原因，不自动放宽约束。

## Neo4j
独立标签与数据集/源版本命名空间，唯一约束和 MERGE 幂等导入。
不删除其他数据。验证快照节点、关系与代表性查询一致性。
连接由环境变量提供，不记录密码；缺少连接时返回明确未验收状态。

## 边界
不做精确库存扣减、价格、营养、替代食材、账号或烹饪调度。
使用 Git 阶段提交和代码审查，首轮不部署。少量规则漏检通过人工审核门禁控制，
不能声称自动解析已完整理解全部菜谱。
