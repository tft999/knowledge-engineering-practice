# CookKG 第一阶段 GraphRAG 汇报设计

## 汇报目标

面向已经了解 GraphRAG 基本结构的课程老师，用四分钟说明 CookKG 如何选择知识图谱构建、
检索和知识注入方案，以及第一阶段实际完成到哪里。汇报应先对齐老师给出的 GraphRAG 框架，
再介绍菜单场景，避免把页面功能当作课题主体。

标题定为：

> CookKG：面向家庭菜单规划的食材知识图谱与 GraphRAG 系统  
> 第一阶段：知识图谱构建与约束检索闭环

## 核心口径

- 最终目标包含知识图谱、检索器和 LLM 知识注入。
- 第一阶段已经完成知识图谱构建、图遍历、约束推荐、FastAPI 和 Web 演示。
- 当前没有完成向量检索和真实 LLM 问答，不能把现有系统称为完整 GraphRAG。
- 默认严格演示使用 10 道人工审核菜谱。
- v2 包含 100 道来源绑定的 AI 辅助标注草稿，人工确认数为 0；53 道只能用于技术联调。
- 知识图谱承担确定性硬约束判断，未来 LLM 只负责基于证据的解释和问答。

## 七页结构

### 第 1 页：课题与阶段定位，15 秒

只展示课题名称、第一阶段范围和一句话目标。第一页不堆叠技术栈、成员履历或统计数字。

讲述重点：最终目标是菜单规划 GraphRAG；本次汇报展示已经完成的知识图谱和约束检索闭环。

### 第 2 页：GraphRAG 技术选择，35 秒

沿用老师 PPT 的三个组成部分，并明确 CookKG 的选择和完成状态：

| 组成部分 | CookKG 方案 | 状态 |
|---|---|---|
| 知识图谱构建 | Markdown 规则解析、AI 辅助预标注、人工审核 | 流程已完成 |
| 检索器 | 当前使用图遍历与约束检索，后续扩展 HybridCypher | 当前阶段已完成图检索 |
| 知识注入 | 将局部子图、原文证据和步骤文本注入提示词 | 下一阶段 |
| LLM | 生成带引用的解释和问答，不决定硬约束 | 下一阶段 |

同时给出目标问题：用户输入库存、忌口、菜数和补购上限，系统返回满足约束的多道菜菜单。

### 第 3 页：数据来源与构建流程，40 秒

展示从数据来源到审核图谱的过程：

```text
HowToCook 固定提交
  -> 370 个 Markdown 全量扫描
  -> 规则解析与食材归一化
  -> AI 辅助标注草稿
  -> 人工审核门禁
  -> 标准图谱与原文证据
```

页面必须包含固定提交 `2b19c9e9`、369 道非模板菜谱、10 道严格审核、100 道 v2 草稿和
0 道 v2 人工确认。用视觉分层区分“来源数据”“草稿数据”和“严格数据”。

### 第 4 页：实体关系与本体，45 秒

展示核心实体：`Recipe`、`Ingredient`、`IngredientCategory`、`Tool` 和 `ChoiceGroup`。

展示核心关系：

```text
(Recipe)-[:REQUIRES]->(Ingredient)
(Recipe)-[:OPTIONALLY_USES]->(Ingredient)
(Recipe)-[:ONE_OF]->(Ingredient)
(Ingredient)-[:IS_A]->(IngredientCategory)
(IngredientCategory)-[:SUBCLASS_OF]->(IngredientCategory)
(Recipe)-[:REQUIRES_TOOL]->(Tool)
```

关系必须同时说明行为语义：必需冲突淘汰菜谱；可选冲突省略；封闭选择组选可用成员；
类别关系用于多跳忌口推理。`HAS_COMPONENT` 只存在于待审核 v2 标准图，不作为当前能力展示。

### 第 5 页：系统架构与数据流，50 秒

用两条视觉路径区分离线建图和在线检索：

```text
离线：HowToCook -> 解析/标注 -> 审核门禁 -> NetworkX/Neo4j + 原文证据
在线：用户约束 -> 归一化 -> 图遍历过滤 -> 联合补购优化 -> FastAPI -> Web UI
未来：局部子图 + 原文证据 -> Prompt 知识注入 -> LLM 带引用回答
```

NetworkX 是当前在线算法的数据源，Neo4j 是图谱持久化和查询验证后端。不得把当前推荐器
描述成 VectorCypher；HybridCypher 是下一阶段的目标检索方式。

### 第 6 页：推理与推荐实例，40 秒

使用一个输入贯穿两类核心能力：

```text
已有：鸡蛋、洋葱、面包片
常备：盐、食用油、黄油、料酒
排除：辣椒
菜数：2
最多补购：2
```

左侧展示图路径“小炒肉 -> 小米椒 -> 辣椒”，说明必需食材命中类别排除后淘汰菜谱。
右侧展示“空气炸锅面包片 + 洋葱炒鸡蛋”，合并补购只有“葱”。强调共享缺料只计算一次。

### 第 7 页：阶段成果与后续计划，35 秒

第一阶段成果：固定数据版本、图谱模型、约束检索、联合补购、4 个 API、React UI、
99 个 Python 测试和 17 个前端测试。

下一阶段按依赖顺序排列：

1. 完成首批 20 道双人独立标注和组长裁决，再逐步审核 100 道草稿；
2. 建立人工评测集，比较关键词与图谱推理、贪心与联合优化；
3. 接入 Neo4j 图检索和向量检索，形成 HybridCypher；
4. 把局部子图和原文证据注入 LLM，完成带引用的 GraphRAG 问答。

页面保留三人分工，但不重复展开已经展示过的技术细节。
