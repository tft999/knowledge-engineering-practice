# CookKG 后端算法与 FastAPI 实施记录

**目标：**以现有 10 道人工审核菜谱完成层级忌口、联合菜单优化、真实 API 和 React 联调闭环。

## 已实施

- [x] 增加版本化人工食材分类，只有已审核关系参与推理。
- [x] 将类别、工具及标准关系写入 NetworkX 图和 Neo4j 导入模型。
- [x] 统一归一化已有、常备和排除输入，并拒绝归一化后的冲突。
- [x] 扩展类别后代、保存稳定路径，分别处理必需冲突和可选省略。
- [x] 保留前 60 候选、1—3 道组合枚举和确定性排序，生成稳定方案 ID。
- [x] 提供健康检查、推荐、菜谱详情和局部图谱四个 FastAPI 接口。
- [x] 通过 lifespan 一次加载图谱，并校验图谱及分类版本。
- [x] 让 React 客户端传递排除条件，并展示被淘汰菜谱的红色推理路径。
- [x] 增加 Python、TypeScript 和真实浏览器联调测试。
- [x] 更新 README、项目定义和验收记录。

## 验收边界

- 当前推荐数据仍为 10 道人工审核菜谱；扩充至 100 道是后续数据工作。
- NetworkX 图是在线 API 数据源，Neo4j 是可选持久化后端。
- 选择组、复合食材、精确数量、营养、价格和 GraphRAG 不在本轮范围。
- Neo4j 没有可用连接时，在线幂等验证保留为未验收项。
