# CookKG 三分钟最终演示脚本

**0:00—0:25，问题。** 普通菜谱搜索只能逐道找菜，无法可靠处理“小米椒属于辣椒”这类
层级忌口，也不会合并两道菜的采购清单。CookKG 用审核后的图谱执行硬约束，再用
GraphRAG 解释结论。

**0:25—1:15，菜单规划。** 输入鸡蛋、洋葱、面包片，常备盐、食用油、黄油和料酒，
排除辣椒，选择两道菜、最多补购两种。展示推荐组合、合并后的补购清单和库存覆盖。
打开图谱解释：`小炒肉 → REQUIRES → 小米椒 → IS_A → 辣椒`，因此该菜被淘汰。

**1:15—2:10，GraphRAG。** 切换“菜谱问答”，提问“为什么不推荐小炒肉？”。指出系统
选择 HybridCypher：文本召回先找到原料证据，固定 Cypher 再扩展菜谱、食材和类别关系。
回答每个事实后带 `[E1]`，点击引用可回到固定提交的原文行；证据不足时系统明确拒答。

**2:10—2:40，实验。** 展示关键词与层级图谱、逐道贪心与联合优化、Vector 与
HybridCypher 三组对照。只汇报冻结测试集真实结果，强调菜单硬约束违反率目标为 0。

**2:40—3:00，边界。** LLM 只组织证据，不判断忌口或补购。100 道数据均须人工审核，
营养推荐留作后续扩展。
