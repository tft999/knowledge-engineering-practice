# Zouyilin06 报告部分：数据标注与知识图谱构建

## 1. 负责内容

本模块把固定版本 HowToCook 的 Markdown 菜谱转换为可验证的结构化数据和食材知识图谱，
为忌口推理、菜谱过滤与联合补购计算提供事实。数据模块不决定推荐排序，也不实现 Web 页面。

## 2. 数据与标注方法

数据源固定为提交 `2b19c9e9ee926fd925a68207a57582a338813f9c`。系统扫描 370 个 Markdown，
识别 369 道非模板菜谱，并从八个类别选择 100 道作为当前校读批次。每个菜谱保存稳定相对路径、
源文件 SHA-256、固定提交链接以及逐字行号证据。自动解析和 AI 校读只产生 `pending` 草稿，
只有当前源哈希与标注摘要均匹配的真实人工审核记录才能把菜谱设为 `confirmed`。

食材关系使用 `required`、`optional`、`one_of` 和 `unknown` 表达做法语义；审核状态独立保存。
并列食材分别建关系，选择项使用带上下界的选择组，工具单独建模，水标为家庭资源，油盐仍是
可采购食材。用量保存 591 条来源观察，其中 463 条精确量、37 条范围、50 条公式和 41 条
保守未解析上下文。程序不换算非标准单位、不求解原文公式，也不把“葱姜蒜共15克”分给每项。
另保存 75 条有原文证据的加工形态。

## 3. 本体与图谱

当前本体草案包含 262 个食材名称、46 个类别、45 条类别上下位关系、259 条食材分类关系和
45 条限定在具体菜谱范围内的别名建议。复合食材只保存原文明确披露的 3 条罐头成分关系，
不能据此推断完整配料或医学意义上的过敏安全。

NetworkX 与 Neo4j 共用同一份标准数据。图谱共有 539 个节点和 1,292 条关系，节点类型包括
Recipe、Ingredient、IngredientCategory、Tool 和 ChoiceGroup。关系包括菜谱所需/可选/选择食材、
工具、IS_A、SUBCLASS_OF 和有限 HAS_COMPONENT。Neo4j 导入以数据集、源提交和接口版本隔离，
在同一事务中替换当前快照，重复导入不会产生重复节点或关系。

## 4. 质量控制与结果

全部 100 道草稿通过源哈希、逐字引文、选择组引用、本体端点、图关系类型及稳定 ID 校验。
连续两次构建的 20 个输出文件逐字节相同；真实 Neo4j 中 539 个节点、1,292 条关系和完整属性
回读均与本地图一致；六个代表性 Cypher 查询与独立 NetworkX 遍历结果一致。最终运行 78 项
自动测试，0 失败、0 跳过，Ruff 静态检查通过。

当前 39 道菜包含 44 个需裁决问题，涉及原文数值冲突、步骤遗漏、商品成分不明、具体食材身份
不明或做法分支边界。系统保留原文问题并把相关菜谱排除在严格数据之外，不猜测作者意图。

## 5. 当前限制

当前 100 道是来源绑定的 AI 辅助草稿，记录的人工确认数为 0，语义准确率没有独立人工金标准，
因此不能报告准确率百分比。课程验收仍需实际完成 100 道人工审核、前 20 道双人独立标注与组长
裁决、至少 10% 交叉复核、三人确认规范和接口，以及与后端的真实联调。仓库提供未预填签名的
审核页面、盲标包、裁决队列、团队记录模板和 100 条评测输入草稿来支持这些工作。

## 6. 可复现命令

```powershell
.venv-data/Scripts/cookkg data-v2 build
.venv-data/Scripts/python scripts/verify_data_delivery.py
.venv-data/Scripts/cookkg data-v2 acceptance
```

连接 Neo4j 后可在验证命令中添加 `--neo4j`，执行两次导入、完整属性回读和六个查询对照。
